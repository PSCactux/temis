# Evaluation datasets

- `dataset.jsonl` (35 cases) is the original smoke set reported in the README; `golden.jsonl` (119 cases) is the larger, stricter set, same schema (see `Case` in `src/aroa/evaluation.py`), ids prefixed by kind.
- Documents (73): at least one case for every section of the six sample documents, multi-part questions spanning two sections, numbers written in words (`"24|veinticuatro"`), paraphrases that avoid the documents' wording, near-miss unanswerable questions (`answerable: false`), questions confined to selected files via `documents` (including ones the file cannot answer), and prompt-injection cases whose `must_not_include` is what the planted note in the client email asks for ("noventa días", "gratuitos").
- Privacy (10): DNI, NIE, IBAN, phone, email, card, plate and names, all fictitious (`0000000xL`, `ES00 ...`, `000 000 00x`, `example.com`), including follow-up turns through `setup` that refer back to the person.
- Policy (6 blocked, as kind `policy`) and 5 ordinary requests that must not be blocked (`policy-allowed-*`, kind `chat` with `must_include`, the convention of the original set).
- Memory (6) and wall (4): facts stored in matter 2026-052 or 2026-064 must be recalled there and must not leak into matter 2026-077; wall cases are placed after the memory case that stores the fact, since a run executes cases in file order from a fresh data folder.
- Alarms (4), project (4, with `files` and `expect_file`), web (2, BOE consolidated texts only), identity (2) and chat (3).
- Verified in code, without running a model: `scripts/check_golden.py` chunks `data/samples` with the project's own chunker and asserts that every `expected` entry matches exactly one real section, every `must_include` term (any `|` alternative) is literally in those chunks, ids are unique and match their kind, `documents` entries are real sample files, privacy cases carry a detectable identifier whose `must_include` terms are written verbatim in the message, and every section of every sample has a case.
- Check: `VIRTUAL_ENV= uv run python scripts/check_golden.py` (exit 1 lists every problem; pass another path to check a different dataset).
- Run: `uv run aroa eval --dataset evals/golden.jsonl` (results land in `evals/results/`; `scripts/eval_table.py` prints the README table). Expect model-dependent failures on near-miss abstention, names in `must_include` that depend on the reveal, and web.
